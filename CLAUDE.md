# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

mimsh.com — the personal site of Mitia Morovov-Sheiner. Static, bilingual (en/ru), vanilla ES modules. No build step, no bundler, no package manager, no tests.

## Running locally

```bash
python3 -m http.server 8080   # from the repo root, then open http://localhost:8080
```

Serving from the repo root is mandatory, not a convenience: every `fetch` and every `@font-face` URL is an absolute path (`/data/nav.json`, `/fonts/…`). Opening an `index.html` over `file://` or serving a subdirectory leaves the page with no navigation, no fonts, and no gallery.

## Page shell

Every page hand-duplicates the same skeleton — there is no templating layer:

```html
<link rel="stylesheet" href="../css/layout.css">   <!-- ../ depth must match the page's nesting -->
<div class="page">
  <aside class="sidebar" data-component="sidebar"><nav id="main-nav" class="main-nav"></nav></aside>
  <main class="content" data-component="content">
    <article class="content-article">…</article>
  </main>
</div>
<script type="module" src="../js/main.js"></script>
```

`js/main.js` runs on `DOMContentLoaded` and bootstraps by `data-component` attribute (`sidebar`, `notes`, `content`, `gallery`), then calls `initZoomableImages()` and `initThemeSwitcher()` unconditionally. `content.js` is currently a stub. Stylesheet/script `href`s are relative (depth-sensitive); everything JS fetches is absolute.

Page-specific behaviour is a second module loaded *after* `main.js` — `js/blog.js` on `/blog/`, `js/lectures.js` on `/lectures/schedule/`. These are side-effecting scripts: they look for their anchor element (`#blog-article`, `#schedule`) and no-op if absent.

## Bilingualism

Both languages are written into the markup side by side and CSS hides the inactive one (`css/layout.css:229`):

```css
html[lang="en"] [lang]:not([lang="en"]),
html[lang="ru"] [lang]:not([lang="ru"]) { display: none !important; }
```

So **any new prose must be authored twice**, each copy carrying `lang="en"` / `lang="ru"` on its own element. Consequences to keep in mind:

- The switcher is rendered by `sidebar.js` from `nav.json`'s `languages` array; it writes `localStorage['site-lang']` and sets `document.documentElement.lang`. It does not reload the page, so JS that renders text must re-render on language change — `blog.js` does this with a `MutationObserver` on the `lang` attribute.
- `<head>` carries duplicated `<title lang="en">` / `<title lang="ru">` tags; `sidebar.js#updatePageTitle` picks the matching one, falling back to the page's title in `nav.json`.
- An unmarked element (no `lang`) shows in both languages — correct for names, dates, and year headings.

## Data-driven content

Structured content lives in `data/` and is rendered at runtime. Prefer adding to JSON over hand-writing markup.

- **`data/nav.json`** — the entire sidebar. `groups` (id, bilingual title, `order`, optional `url` defaulting to `/<id>/`) and `pages` (url, bilingual title, `groups[]` membership, `order`). A page can belong to several groups. External `http(s)` urls get `target="_blank"`; `t.me` urls get a Telegram icon appended. Active state and initial group open/closed state are derived by comparing the current pathname.
- **`data/galleries/<name>.json`** — an array of `{source, full, preview, alt, caption}`, generated by `scripts/build-images.py` (see Images). `preview` is the thumb, `full` the large derivative, `source` the master it came from. `gallery.js` resolves `<name>` from the `data-gallery` attribute, else from the page's parent directory name (`/photography/neon/` → `neon.json`). Edit `alt`/`caption` here by hand; everything else is regenerated. Pages using a gallery must also link `css/gallery.css`.
- **`data/posts.json` + `blog/posts/<slug>.html`** — posts are HTML *fragments* (no shell, start at `<h2>`) injected into `#blog-article`. A `_ru` / `_en` slug suffix is what filters a post by language; a slug without a suffix shows in both. `?post=<slug>` selects a post; no param means the newest. Titles come from `posts.json`, the date line is generated.
- **`data/lectures.json` + `js/lectures.js`** — upcoming vs. past and the year headings are *derived from `date`*, never hand-declared. A full `YYYY-MM-DD` in the future is upcoming; a year-only date (`"2025"`) is always past. This was the point of the migration — an announcement can't go stale. Both language variants of each entry are emitted from one JSON record.

`/lectures/` is a landing page (intro + section links, following `photography/index.html`); the schedule itself lives only at `/lectures/schedule/`.

## Styling

`css/layout.css` is the whole design system, organised in 11 numbered sections documented in its header comment. Change colour/size/spacing via the tokens in section 2 first; layout dimensions (`--sidebar`, `--content`, `--notes`, `--gutter`) are tokens too. The layout is a 3-column editorial grid: sidebar · content · notes rail.

Theme: `data-theme="dark"|"light"` on `<html>`, stored in `localStorage['theme-preference']`, with a `prefers-color-scheme` fallback under `:root:not([data-theme="light"])`. Any new colour needs a definition in all three places (`:root`, the media query, `[data-theme="dark"]`).

Self-hosted fonts (PP Right Grotesk, plus the project fonts Krokodeilaki and Avant-Glagolitic from `/files/fonts/`) sit alongside a Google Fonts `@import` for IBM Plex Sans and Noto Serif.

`css/gallery.css` is opt-in per page — required for both the gallery grid and the shared lightbox.

## Two component conventions worth knowing

**Sidenotes (Tufte-style).** Put `¹` — the literal superscript-one character — inside a `<p>` or `<li>`, and place a `<div class="note">` immediately after it. `notes.js` renumbers the markers sequentially, wraps the pair in `.note-wrapper`, and CSS floats the note into the right rail on desktop / inline on mobile. The marker character is the trigger; without it the note is ignored.

**Zoomable images.** Add `class="img-zoom"` to any `<img>` and link `gallery.css`; it reuses the gallery lightbox singleton. Caption comes from `title` or `data-caption`. Documented in `.agent/docs/img-zoom.md`.

## Images

**Never reference a file in `img/` from a page.** Masters there are archives — full-resolution and never served. Pages and gallery JSON point at WebP derivatives under `img/derived/`, built by `scripts/build-images.py`:

```
img/photos/neon/DSC_1596.jpg                  master, 3784 KB, not served
img/derived/photos/neon/DSC_1596.thumb.webp    400w,     8 KB, gallery grids
img/derived/photos/neon/DSC_1596.large.webp   1600w,    44 KB, lightbox + inline
```

```bash
scripts/build-images.py             # incremental build + gallery sync (~0.1s when current)
scripts/build-images.py --force     # re-encode everything
scripts/build-images.py --dry-run   # report changes, write nothing
```

Requires `cwebp` (`brew install webp`). Both derivatives and `.image-manifest.json` are committed, because nothing builds on deploy.

The workflow for adding images is: drop files into a folder under `img/`, run the script, commit. It encodes both tiers, prunes derivatives whose master is gone, and syncs `data/galleries/*.json` — appending new entries, dropping vanished ones, and **preserving hand-written `alt`/`caption`** by matching on each entry's `source` field. New entries get blank `alt`/`caption` for you to fill in; the script prints which ones.

Things that will bite you:

- **Scope is exclude-based** — everything under `img/` except `logos/`, `icon-random/`, `previews/`, and the favicon. New folders are picked up automatically; if something must stay un-derived, add it to `EXCLUDE_DIRS`/`EXCLUDE_FILES`.
- **Gallery-to-folder mapping is explicit** in `GALLERIES`, because the names don't map uniformly — the `colour` gallery reads from a folder spelled `color`, and the posters live in `poster-every-day - 1`. A new gallery needs an entry there.
- **Rebuilds are keyed on content hash plus a settings string.** Changing `TIERS` re-encodes everything on the next run, by design.
- **Derived filenames drop the source extension** (`DSC_1596.jpg` → `DSC_1596.thumb.webp`), so two masters in one folder sharing a stem but differing in extension would collide. There are none today.
- Never upscales: a master narrower than the tier width is encoded at its own width.

The three legacy `previews/` folders are superseded and unreferenced, but deliberately kept on disk. `scripts/make-previews.sh` was deleted.

Do not touch `archive/` (gitignored, the previous version of the site). `temp/` holds superseded copies of the `art/` pages.
